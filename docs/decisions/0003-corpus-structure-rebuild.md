# ADR 0003: 코퍼스 항·호·목 구조 복원 및 청킹 방식 변경

- 날짜: 2026-09-17
- 상태: 확정

## 배경

검색 평가 세트를 만들다가 정답 근거가 색인에 없는 문항을 발견.
"사적연금 분리과세 기준 금액"의 근거인 소득세법 제14조 ③항 9호 다목("연 1천500만원 이하")이
Elasticsearch 어디에도 없었음.

원인은 수집 데이터와 청킹의 조합.

- 수집 스크립트는 조문을 `content`(전체 텍스트)와 `paragraphs`(항 단위 구조) 두 형태로 저장.
  `content`에는 목(가·나·다)까지 들어갔지만 `paragraphs`에는 호까지만 들어감
- 청킹은 1,200자 넘는 긴 조문을 `paragraphs` 기준으로 잘랐음
- 결과적으로 긴 조문 507개 중 **236개에서 목이 통째로 누락** (약 16만 자, 97%가 세법)
- API 원본 응답은 보관하지 않고 파싱 결과만 저장했음

수집 단계 결함도 추가로 확인.

- 목이 여러 줄이면 파이썬 목록 모양 문자열(`['가. …', '1) …']`)로 저장됨 (139줄)
- 16번째 항부터는 `<16>`, `<17>` 표기 사용
- 169개 조문은 표·계산식이 `<img>` 태그로만 들어 있어 텍스트가 없음

## 결정

- **재수집 대신 `content`에서 구조 복원**: `content`는 항·호·목이 한 줄에 하나씩 있어 줄머리 기호로
  구분 가능. 재수집하면 8/19 이후 개정분이 섞여 "파싱을 고친 효과"와 "법이 바뀐 효과"를 구분할 수 없음
- **원본 보관**: 수집본은 `*.json.bak`으로 두고 복원본을 같은 이름의 `*.json`으로 저장
- **청킹 방식 변경**
  - 긴 항은 글자 수가 아니라 호·목 줄 단위로 묶어 자름 (문장이 중간에 끊기지 않게)
  - 한 항이 여러 청크로 나뉘면 뒤쪽 청크에 짧은 항 문장·호 문장을 다시 붙임
    ("다. 연 1천500만원 이하"만 떨어져 문맥을 잃지 않게)
- **재발 방지 테스트**: 코퍼스 전체에서 조문의 모든 줄이 어떤 청크에든 들어 있는지 확인.
  예전 동작을 재현하면 빠진 줄 2,294개를 잡아냄

## 결과

- 복원 검증: 기존 `paragraphs`와 항·호 1,567/1,567 일치, 목 1,941개 복원
- 청크 5,713 → 5,798, 재색인 실패 0건
- "사적연금 분리과세 기준 금액" → BM25 4위 (이전에는 답이 색인에 아예 없었음)

## 남은 문제

- **`<img>` 조문 169개**: 표·계산식 속 숫자는 검색 불가. 별도 처리 방안 필요
- **용어 차이**: "IRP 연간 납입 한도"의 근거(소득세법 시행령 제40조의2 가목 1,800만원)는
  "연금계좌"라는 말만 써서 BM25·벡터 모두 10위 밖. 평가 세트로 측정 후 대응
- **숫자 표기**: nori가 "1천800만원"을 `1/천/800/만/원`으로 분리. "1800만원"으로 검색하면 안 맞을 수 있음
- **수집 스크립트 자체는 미수정**: 원본 응답을 저장하고 파싱을 분리하는 구조로 개편 필요
