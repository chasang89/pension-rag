# 연금·절세 RAG 프로젝트 — 개발 스펙 v2

> v1(FinDoc RAG)에서 주제 확정, 레퍼런스 검증, 임베딩 모델 교체를 반영한 개정판 (2026.07.28)

## 1. 프로젝트 개요

- **주제**: 연금·절세 특화 문서 검색 RAG — IRP / ISA / 연금저축 / 퇴직연금
- **한 줄 소개**: "IRP 세액공제 한도 얼마예요?" 같은 질문에 법령·안내자료·약관 원문을 근거로 인용해 답하는 시스템
- **목표**: 정규직 이직용 포트폴리오 1호. 5개월 개발, 이후 2번째 포폴로 이어감
- **커밋 목표**: 약 50개 (월 10개꼴), 개발 과정과 사고 흐름이 드러나도록 기록

### 주제 선정 근거 (면접 답변용)

- 금융권 11년 경력(신한카드 AML·여전법 규제 대응, KB 마이데이터, 예탁결제원)과 직결
- 현재 퇴직연금 프로젝트 수행 중 → 실무 도메인 지식 즉시 반영 가능
- 국세청이 동일 방향의 "생성형 AI 국세상담 서비스"를 RAG 기반으로 구축 중 → 시장 검증됨
- 연금·세금 특화 한국어 오픈소스 RAG는 아직 없음 → 차별화 확보
- 답이 여러 문서(법령+시행령+감독규정+약관)에 흩어져 있는 도메인 → RAG가 가장 빛나는 시나리오

## 3. 기술 스택

| 레이어 | 기술 | v1 대비 변경 |
|---|---|---|
| 게이트웨이 | Kotlin + Spring Boot | 유지 |
| RAG 코어 서비스 | Python + FastAPI + LangChain | 유지 |
| 검색 엔진 | Elasticsearch 8 (텍스트+벡터 동시 저장) | 유지 + **nori 한국어 분석기 적용** |
| 임베딩 | **bge-m3 (다국어) 또는 한국어 벤치마크 후 선정** | **변경** (기존 BGE-small은 영어 중심이라 한국어 성능 부족) |
| 재순위 | CrossEncoder (경량, 한국어 지원 모델 검토) | 유지 |
| LLM | Claude / OpenAI API | 유지 |
| 배포 | Docker Compose → AWS EC2 (t3.medium) | 유지 |

## 5. 핵심 파이프라인

**문서 등록**: 업로드 → 텍스트 추출 → 청킹 → 임베딩 → Elasticsearch 색인

**검색/답변**: 질문 → BM25(nori)+벡터 병렬 검색 → RRF 융합 → CrossEncoder 재순위 → LLM 답변 생성 (근거 조항·출처 인용 필수)

## 6. 도메인 특화 지점 (차별화 포인트)

1. **청킹 전략** — 법령은 조항 단위(제N조 제N항), 안내책자·약관은 문단 단위로 이원화 실험. 결과를 README에 기록
2. **금융 엔티티 사전** — IRP, ISA, 연금저축, CDD/EDD, 세액공제, 과세이연 등 용어 사전 구축 → 검색 정확도 개선
3. **근거 인용 프롬프트** — "반드시 근거 조항(법령명·조항 번호) 명시" 지시로 할루시네이션 방지
4. **연도별 개정 대응** — 세액공제 한도처럼 연도별로 바뀌는 정보에 시행 연도 메타데이터 부여 (예: 2023년 900만 원 상향)
5. **조건 분기 정확성** — 총급여 5,500만 원 기준 공제율 차이 같은 분기를 정확히 답하는지 평가셋 구축

### 면접 예상 질문 방어

- **"청킹하면 조항 의미가 깨지지 않나?"** → lexdiff는 그 이유로 Verbatim RAG(법제처 API 원문 주입)를 택했지만, 본 프로젝트 코퍼스는 안내책자·약관 등 API 조회 불가능한 비정형 문서가 핵심이라 청킹 기반이 적합. 조항 단위 청킹으로 완화
- **"임베딩 모델 왜 이거 골랐나?"** → AutoRAG 한국어 벤치마크 근거로 답변
- **"왜 게이트웨이를 분리했나?"** → 인증·라우팅·백프레셔 등 Java/Kotlin 강점 영역 분리, 본인 주력 스택 어필

## 7. 인프라·비용 전략

- **개발 (1~4개월)**: 로컬 Docker Compose — 0원
- **배포 (5개월~)**: EC2 t3.medium, 평소 Stop / 데모 때만 Start
  - 24시간 가동 시 월 약 6만 원 (인스턴스 $38 + EBS $3) → 비추천
  - Stop 상태 유지 시 EBS 보관비만 월 3~4천 원
  - **목표: 월 5천 원~1만 원**
- 온오프 자동화 스크립트(또는 Lambda)도 포폴 소재로 활용
- 주의: t3.medium RAM 4GB에서 ES(JVM 힙 2GB)+FastAPI+임베딩 모델은 빠듯 → 힙 튜닝 or 인스턴스 분리 검토. 해결 과정 자체를 README에 기록
- LLM API 비용: 데모 수준 월 수천 원 이하

## 8. 개발 시간 계획

- 주 5시간 기준, 5개월 ≈ 108시간
- **Core (~70h)**: 파싱 → 청킹 → 색인(nori) → 하이브리드 검색+RRF → LLM 연동 → Docker 배포
- **Stretch (~40h)**: CrossEncoder 재순위, 임베딩 벤치마크, 엔티티 사전, 평가셋, UI
